# MCP 项目演示指南

目标是用 3～5 分钟展示一次真实链路：**AI 客户端发现工具 → 发起调用 → MCP Server 执行 → 客户端展示结果 → 管理后台查看记录**。

本文件是演示和录屏脚本，不代表已完成联调或已有录屏文件。先按 [README](../README.md) 在独立演示数据库中启动后端与前端，再实际检查每一步。

## 演示前准备

1. 后端运行于 `http://localhost:8090`，管理前端运行于 Vite 输出地址，默认 `http://localhost:5173`。
2. 用初始化 SQL 中的公开演示账号 `demo-admin` / `admin123` 登录管理界面。
3. MCP 客户端连接 `http://localhost:8090/mcp`，请求头为 `Authorization: Bearer mcp_dev_token`。
4. 刷新客户端工具列表，确认能发现 `hello`、`calculate` 和 `echo_dynamic`。若缺少工具，检查用户角色权限、Token 能力选择和工具发布状态。
5. 录屏只显示模拟输入、演示账号和本地地址；关闭真实凭据、业务数据库或私人文档所在的窗口。

如果客户端需要模型，先完成其模型连接配置。模型提供方和费用不由本 MCP 服务处理。

## 0:00～0:30：介绍项目

可以这样讲：

> 这是一个基于 Spring Boot 和 Spring AI 的 MCP 工具服务端。它把 Java 方法和 Groovy 动态脚本开放给 AI 客户端，并通过角色、Token 和审计记录管理工具调用。接下来演示工具发现、一次动态工具执行和后台审计。

打开仓库 README 或管理后台，简单指出工具、Token、审计三个部分。对于课程或团队来源，如实说明自己的实现与修改范围。

## 0:30～1:15：连接与内置工具

展示客户端已连接的 MCP 服务和工具列表，再输入：

```text
请调用 bear-mcp-demo 的 hello 工具，name 传入 MCP 演示，展示实际工具返回结果。
```

对应参数：

```json
{"name":"MCP 演示"}
```

预期可观察到问候文本和当前 MCP 用户。重点展示客户端的工具调用记录，不能只展示模型自己写出的一段问候。

可以追加一个计算示例：

```text
请调用 calculate 工具计算 12.5 乘以 4，展示工具执行结果。
```

```json
{"left":12.5,"right":4,"operator":"multiply"}
```

预期结果为 `50`，具体 JSON 展示形式由客户端决定。

## 1:15～2:15：动态 Groovy 工具

在客户端输入：

```text
请调用 echo_dynamic 工具，message 传入“这是我的 MCP 项目演示”，展示工具返回的 message 和 currentUser。
```

对应参数：

```json
{"message":"这是我的 MCP 项目演示"}
```

公开演示版的 SQL 种子脚本将 `echo_dynamic` 设置为纯回显：

```groovy
return [
  message: params.message,
  currentUser: userName
]
```

预期返回相同的 `message` 和演示用户身份。它没有关联外部 HTTP 配置，不需要云服务凭据。

打开后台的动态工具信息，说明工具名称、输入 Schema 和脚本来自数据库。可以解释 `runRequest` 和 `runSql` 是扩展入口，需要预先绑定允许访问的 API 或数据源；基础录屏不必调用这些外部依赖。

## 2:15～3:00：查看调用审计

打开管理端“审计日志”，刷新后找到刚刚的 `echo_dynamic` 调用，展示：

- 工具名称和调用时间。
- 用户信息、请求与响应摘要。
- 执行状态和耗时。

解释这些记录如何帮助确认“调用了哪个工具、输入是什么、是否成功”。若未立即显示，等待片刻并刷新；如仍缺失，应先排查服务或数据库日志，不能将未出现的记录描述为已经保存。

## 3:00～4:00：可选的权限演示

在独立演示环境里，将客户端请求头中的 Token 临时改为 `invalid-demo-token`，重新连接。预期服务端拒绝请求，返回 HTTP 401。随后恢复 `mcp_dev_token` 并重新连接。

这一操作演示 Token 鉴权，不等同于完整的角色权限测试。若要展示细粒度权限，可另建测试 Token，仅选择一个已授权工具，再刷新客户端工具列表进行比较；不要禁用当前管理员账号。

## 4:00～5:00：说明实现与边界

可以这样结束：

> 这里展示了从 MCP 客户端发现并调用工具，到服务端执行并留下审计记录的流程。工具可以由 Java 实现，也可以由数据库中的 Groovy 脚本扩展。Resource、Skill 文件存储和外部数据源是额外集成，需要单独配置和验证。

展示你能解释的代码位置，例如 `ApiKeyAuthFilter`、`McpToolsListFilter`、`McpToolsCallFilter` 和 `GroovyScriptEngine`。不要把脚本限制描述成生产级安全沙箱，也不要把本服务端描述成独立完成规划和对话的 Agent。
